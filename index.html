Sistema de gestión para un club de barrio

demo · próximamente

Trabajo práctico final de Analista de Sistemas (ORT), basado en el proceso real de Club Imperio Juniors.

Problema

Socios, actividades, asistencias y cobranzas se manejaban en planillas de Excel separadas: datos duplicados, cupos controlados a mano, sin historial de asistencia confiable.

Qué construí

  • Socios y membresías, actividades y comisiones con cupo
  • Inscripciones, asistencia por clase y clases de prueba para no socios
  • Importación masiva de socios desde Excel/CSV con validación fila por fila
  • Dashboard, login y roles (ADMIN / USER)
JavaSpring BootSpring Security · JWT JPA / HibernatePostgreSQLSwagger React + TypeScriptViteMUITanStack Query Tests E2E · 330+ verificaciones

Resultado

El proceso real del club, llevado a un sistema completo: API REST, frontend y más de 330 verificaciones automatizadas que validan los flujos de punta a punta.

Cómo usé IA. El relevamiento, el modelo de datos, las reglas de negocio y la primera parte del backend los hice yo. Para completar el backend (incluida la autenticación) y para el frontend trabajé con IA. Mi rol fue definir qué construir, revisar el código capa por capa (controller, service, repository) y validar el comportamiento con la suite de pruebas.

Ordenar la administración de un club con lo que ya usaban

caso · análisis funcional

Club Imperio Juniors · Administrativo y mejora de procesos (2024–2025)

Situación

Socios, actividades y pagos se llevaban en planillas sueltas, con socios duplicados. El control de pagos se hacía a mano y había que repetirlo cada 5 días.

Qué hice

  • Relevé el circuito administrativo completo con quienes lo hacían a diario
  • Depuré el padrón de socios hasta dejar un registro único
  • Automaticé el control de pagos con planillas vinculadas, sin cambiar de herramienta
  • Capacité al personal administrativo para usarlas en su trabajo diario

Resultado

Se eliminó una verificación manual que se repetía cada 5 días, y el padrón quedó confiable. Ese relevamiento fue la base del sistema de gestión de arriba.

Implementación de un ERP para el sector agropecuario

caso · sin código ni capturas

Mantis · Trainee analista funcional (2026). Software propiedad de la empresa: se describe el trabajo, no el producto.

Contexto

ERP desktop y web para ganadería, acopio, frigoríficos y consignatarios de hacienda. 8 empresas cliente y 9 proyectos, con 3 a 4 en simultáneo.

Qué hice

  • Relevamiento y documentación de pedidos, facturación, cuenta corriente, consignación y crédito: historias de usuario en Jira, especificaciones funcionales e instructivos
  • Especificación de integraciones por API REST: una billetera virtual para adelanto de cobros y el control de stock de un frigorífico
  • Corrección y ampliación de un modelo de ponderación de riesgo crediticio
  • QA funcional junto al equipo de desarrollo
  • Instalaciones remotas de servidores y resolución de incidencias en SQL Server e IIS a partir de logs

Resultado

Le propuse a un cliente reacio al cambio migrar a la versión web. La empresa negoció la propuesta y el cliente migró.
